# Starter review

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It subtracts a wall-clock shift time without converting the stored UTC instant to IST or selecting the prior shift date for an overnight shift. | A 22:00-06:00 employee punches at 05:55 IST; lateness is calculated against the wrong day. | Convert instants to IST and use the attendance date to construct that shift's start. |
| 2 | `compute_late_minutes` | It truncates elapsed minutes before applying the grace threshold, so a punch 10 minutes and 1 second late is treated as within grace. | For a 09:30 shift, 09:40:01 incorrectly returns 0 instead of 10. | Truncate instants to seconds, compare the full duration with 600 seconds, then floor elapsed minutes. |
| 3 | `compute_work_hours` | Python's `round` uses ties-to-even rather than the contract's half-up rounding. | A duration whose hour value is exactly halfway at two decimal places rounds down unexpectedly. | Use `Decimal` with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | It constructs a same-day shift end, so overnight shifts get the wrong end instant; it also mixes a timezone-aware value with a possibly naive stored punch-out. | A 22:00-06:00 shift punched out at 06:40 IST can fail or calculate no overtime. | Build the shift end on the next IST calendar day for overnight shifts and compare aware instants. |
| 5 | `EmployeeIn` | Employee identifiers, email, lengths, dates, shift syntax, and unequal shift bounds are not validated. | Send a malformed code, impossible date, bad time, or equal start/end. | Add schema constraints and explicit date/shift validation. |
| 6 | `create_employee` | The duplicate check and insert are separate operations, so concurrent requests can both pass; no unique index is created. | Submit the same `emp_code` concurrently. | Create a unique index at startup and translate `DuplicateKeyError` to 409. |
| 7 | `create_employee` | `created_at` uses a naive local clock and is returned as a datetime instead of epoch milliseconds. | Run under a non-UTC host timezone and inspect the response shape. | Store a truncated UTC instant and serialize it as epoch milliseconds. |
| 8 | `list_employees` | Page offset starts at `page * page_size`, skipping the first page; `total` ignores the department filter and results are unsorted. | Request page 1 and a department filter. | Use `(page - 1) * page_size`, count the same filter, sort by `emp_code`, and cap page size. |
| 9 | `punch_in` | An unknown employee causes an index error; the timestamp is interpreted in machine-local time and seconds are accepted as milliseconds. | Punch for a missing employee or send a seconds-looking timestamp. | Return 404 for unknown employees, validate epoch milliseconds, truncate, and convert to UTC/IST correctly. |
| 10 | `punch_in` | Date assignment ignores IST/overnight rules, and the check-then-insert race allows duplicate daily attendance. | Punch around midnight for an overnight employee or send parallel identical requests. | Derive the R1 attendance date and rely on a unique `(emp_code, date)` index for atomic conflict detection. |
| 11 | `punch_in` | It does not validate the requested attendance status and uses employee shift data without an employee-existence guard. | Send `ABSENT` to punch-in or use an unknown employee code. | Restrict status to presence statuses and return 404 when the employee is missing. |
| 12 | `list_attendance` | It reads and sorts the full matching collection in Python, which is unbounded and slow at the target size; ties have no deterministic employee sort. | Exercise it against a large collection and request multiple records on one date. | Count and page in MongoDB using the required stable sort and indexes. |
| 13 | `list_attendance` | It accepts invalid pagination and reversed dates, and does not validate status or date syntax. | Try page 0, page size 101, an invalid date, or `date_from > date_to`. | Add query validation and explicit range checking. |
| 14 | `list_attendance` | Returned records expose BSON datetimes (including nested history) instead of epoch milliseconds, and legacy defaults are absent. | Read a record with a history entry or a legacy record missing `history`/`half_day`. | Serialize every instant (including history changes) and supply the documented defaults. |
| 15 | `health` | It always returns 200 without checking MongoDB readiness. | Stop MongoDB and call `/health`; the starter still reports `ok`. | Ping MongoDB and return 503 when the database is unavailable. |

**Reviewed and not defects:** the natural employee key is `emp_code`, and `history` belongs only to manual corrections; both match the data model. The starter's list-attendance page slice formula itself was correct for one-based pages, though it was applied only after loading every matching record.
